# 验证脚本

```bash
pnpm test                      # 跑全部 8 个文件
node --import ./test/_loader/register.mjs test/limit-edge2.mjs   # 只跑一个
```

这些脚本**直接 import `src/utils` 下的真源码**（不是复制一份逻辑），只做纯计算断言，
不需要浏览器。因为 Vite 允许省略 `.js` 后缀而 Node ESM 不允许，所以统一用
`_loader/register.mjs` 补后缀。

| 文件 | 覆盖范围 |
| --- | --- |
| `iso-week.mjs` | ISO 周逐日对拍：2010-01-01 ~ 2040-12-31（11323 天 / 1619 个 ISO 周）与独立 `Date` 参考实现 0 差异；周内 7 天一致性；1990~2060 年周数；宽松/非法输入 |
| `strict-parse.mjs` | 严格解析：`2026-13-01`、`2026-02-30`、`2026-02-29`（非闰年）、`-00-` 一律拒绝，`2024-02-29` 合法 |
| `period.mjs` | 维度切换 A~J：日→年→日 往返无损、跨年周归属、月末/闰日裁切、`projectDay`、四种维度 parse/format 往返、非法输入 |
| `drill.mjs` | 钻取口径 K~R：`anchor` / `start` / `end` / `today` 的落点；底线「变粗永远以锚点为准」「区间恒含锚点」 |
| `drill-cost.mjs` | 非 `anchor` 口径丢位置的代价（日 → 周 → 日 会漂到周末/周初） |
| `limits.mjs` | T-n 限制 S~V：口径解析（`T` / `T-1` / `T+7` / 小写 / 数字 / 绝对日期 / 非法值）、`resolveLimits` 写反自动换回、含端点判定、夹取、区间与限制的交集 |
| `limit-edge.mjs` | T-n 边缘 W~Z：`T-30` 跨月/跨年/闰年；今天 `2026-10-12` 时各维度可点性；越界夹取；极端限制 |
| `limit-edge2.mjs` | T-n 边缘 AA~AF：今天=周一 vs 周四是「本周能不能点」的分水岭、边界落在周中、贴边、属性测试（11626 个可选区间 × 279024 组口径/前值组合）、`T-n` 的日历日语义与 `Date` 参考对拍 |
| `limit-t2.mjs` | T-2 场景 AG~AK（数据滞后两天：跨月/跨年/闰日解析、本周从周三起才有得点、上限落到上月时当月整月灰掉、上限落在跨年周 `2026-53`、只留 T-2、`earliest="T-32" latest="T-2"` 的 30 天窗口）+ AM（今天 `2027-01-02`：T-1 时 `2027` 年/`2027-01` 月还能点，T-2 时整年整月灰掉，只剩跨年周 `2026-53` 的 4/7 天）+ AL 通用规律（`T-n` 时各维度从第 n+1 天起才可点） |

`limit-edge2.mjs` 的 AD 组是**属性测试**，也是这几套里最值钱的：对每个「面板里选得到的区间」，
四种钻取口径 × 六个历史锚点都必须满足

1. 锚点仍然落在该区间内（夹取不能把锚点挤出选中区间）；
2. 锚点仍然落在 `earliest ~ latest` 内（写出去的 `v-model` 不会被自己的限制打回来）。

改了 `period.js` 里的 `anchorFor` / `clampToLimits` / `periodWithinLimits` 之后，这一组最容易抓到回归。
